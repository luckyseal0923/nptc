# 程式檢視修正與部署

本次依使用者選定清單實作，首次啟用仍沿用姓名／Email／手機核對，不加入新的身分核對政策。既有量表版本、原始作答與計分規則不改寫。

## 資料庫

既有量表環境先確認版本 2026102905，再執行完整 `supabase/upgrade-review-hardening.sql`。新版為 **2026103001**，可重跑，不搬移資料。新增的刪除影響查詢與稽核只給系統管理者；一般老師的量表摘要與逐題查詢仍受梯次權限限制。

整梯次永久刪除必須重新讀取學員、OSCE 評分、問卷發布及作答筆數，確認完整範圍、輸入梯次名稱、重新驗證目前系統管理者密碼。伺服器鎖住梯次並核對資料指紋後才刪除；稽核只保留操作者、時間、刪除範圍，不保留被刪除的原始答案。

量表頁會檢查此版本；未升級時顯示明確訊息，OSCE 基礎功能的最低版本仍為 2026100701。GitHub 前端發布不會自行執行 SQL。

## 前端與 Edge

- 密碼重設／重新確認信箱保留有效問卷 UUID；短網址轉為同站可驗證的問卷路徑，拒絕外站回跳。
- 分析預設目前梯次，僅下載摘要與分數，點選「查看原答」或分數才讀逐題內容；「所有可檢視梯次」仍可明確選取。
- 未送出問卷離開時提醒；不將真實作答寫入瀏覽器持久儲存。瀏覽器對返回手勢／手機強制關閉的提醒能力有限。
- Edge `student-activate` 以串流限制 4096 位元組，含無 Content-Length 的請求；過大回 413，未通過時不呼叫名冊 RPC。伺服器函式須另部署，前端 GitHub 推送不等於 Edge 已更新。

## 安全標頭

根目錄 `_headers` 與產物的 `_headers` 使用同一份規則：nosniff、Referrer-Policy、禁止嵌入、HSTS 與 CSP。Zeabur 的靜態主機應讀取根目錄規則；需以正式 HTTP 回應確認，不能僅檢查檔案存在。官方說明：[Zeabur 靜態網站](https://zeabur.com/docs/en-US/guides/static)。

GitHub Pages 不提供專案自訂 HTTP 標頭，因此 HTML 同時加入可生效的 CSP 與 referrer meta；frame-ancestors／X-Frame-Options／nosniff 仍須主機支援，不能宣稱 meta 可以取代。CSP 僅允許本站資產及本專案 Supabase 連線；日後更換 API 網域須同步調整 `_headers`。

## 維護檢查

公開金鑰檢查與更新流程見 `key-renewal.md`。`pnpm check` 含機密掃描、型別與回歸測試；`pnpm check:api` 會區分 JWT／金鑰錯誤、缺 RPC、網路失敗及預期權限拒絕。部署後再核對 SQL 版本、正式標頭與問卷入口。
