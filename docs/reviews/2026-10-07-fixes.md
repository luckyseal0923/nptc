## 其他整併修正

- PGlite 納入正式測試依賴；`pnpm check` 集中執行，CI 部署前必須通過。
- 展示模式對齊公布、名冊鎖定、題目版本、建立重試與官方醫院清單，仍不模擬真實 SMTP、Auth 與系統管理者敏感操作。
- 首頁、登入、學員、後臺與分析分開載入；原本約 614 kB 的單一 JavaScript bundle 已拆開，最大的單一 JavaScript 檔為 215.69 kB，初始入口為 193.23 kB（均未壓縮），不再出現 500 kB 警告。
- 個人歷史的梯次數取完整歷史，避免受到目前分析篩選影響。
- 提供唯讀 SQL，偵測舊資料是否出現已公布／已評分題目缺漏或分項超出配分；不猜測修正既有成績。

## 已完成驗證與限制

`pnpm check` 通過：前端與 Edge TypeScript 檢查、14 支測試檔、共 32 個 Node test 記錄（含父測試），其中新增現行 SQL 有 14 組情境，另測有資料的舊環境升級與展示模式規則。SQL 測試使用 PGlite，沒有連線正式資料庫。

`pnpm build` 通過。官方醫院資料下載失敗，建置採用 `2026-09-08T16:10:27.462Z` 的既有快取，產生 139 家院名種子；不能宣稱名冊已即時更新。前端正式清單由最後一次 SQL 安裝決定。

瀏覽器使用本機模擬 RPC 與虛構學員驗證公告摘要／名冊禁用、未公布題目可評分、跨梯次清空選取／門檻切換、已註冊 Email 唯讀、成功寫入後讀取失敗提示、醫院載入失敗仍顯示成績、封存分析與完整歷史計數。這些畫面驗證沒有使用正式帳號或寫入正式資料。

現行升級也會重新撤銷舊批次總分 API 的權限，並重新確立首次啟用名冊核對只有 service_role 可呼叫，已模擬舊權限被放寬後驗證修復。後臺管理員在學員頁不提供 Email 變更入口，避免更動既有後臺身分。

Edge SDK 固定為與本機一致的 2.115.0；TypeScript 檢查使用本機 Deno 宣告，Handler 測試使用模擬 Supabase；尚未驗證原生 Deno runtime、正式 gateway、SMTP 或實際信箱確認。PGlite 驗證版本拒絕與資料一致性規則，沒有對正式服務做多人競爭或負載測試。
