# 學習分析

## 使用方式

1. 後臺導覽列點「學習分析」。首次開啟會沿用課程管理目前選取的梯次。
2. 選「目前梯次」並切換梯次，或選「所有梯次」。
3. 可篩選科別、護理年資、醫院、單位、首次 OSCE，並搜尋姓名或 Email。
4. 查看整體摘要、成績與 Global Rating 分布、各梯次總覽（所有梯次模式）、各題表現、背景分組及學員清單。
5. 點姓名查看所有梯次的日期、題目、分數、評等、判定與老師回饋。個人完整歷史不受上方篩選限制。
6. 成績或名冊更動後，按「重新整理」。重新整理會回到預設篩選。

## 計算定義

- 學員人數：以去除前後空白並轉小寫的 Email 合併計算。同名不同 Email 不合併；缺少 Email 時，每筆名冊獨立計算。Email 變更不會自動串接。
- 應評分：範圍內每筆名冊乘以該梯次目前設定的題目數。
- 平均分數：以學員每題的有效數字分數計算。零分有效，未評分不計入。
- 及格率：僅計入有分數且該題有及格門檻的紀錄。門檻來自原後臺查詢，不依篩選後子群重算。等於門檻視為及格。
- 跨梯次統計是每筆評分加權；題目或人數較多的梯次佔較多筆數，不是各梯次平均的平均。
- Global Rating 分布：統計 1–5 的有效評等。
- 背景欄位取各梯次名冊目前保存的值，並非歷史快照。同一學員可能出現在不同背景分組。
- 依日期排列個人紀錄；缺少日期的題目放在最後。不同題目的分數不能直接當作進退步指標。
- 包含未公布成績，沿用現有後臺人員權限。

## 技術與部署

沿用 `nptc_teacher_data` 讀取各梯次，最多同時讀取四個梯次。任何梯次載入失敗都不呈現局部總計，而是顯示錯誤與重試。頁面離開時中止查詢。資料僅保留在頁面記憶體，不另存瀏覽器儲存區。

本次不新增資料表或 RPC，不需新增 SQL migration。沿用既有後臺 Supabase 設定。分析頁採按需載入。當梯次數與名冊量大幅增加時，可再改為伺服器端彙整及分頁。

## 驗證

- `node --experimental-strip-types tests/learning-analysis.mjs`：零分／未評分、分母、跨梯次門檻、Email 串接、歷史、資料缺漏、載入錯誤。
- `node tests/student-activation.mjs`：既有資料庫名冊、成績及權限回歸。
- `npx tsc --noEmit`、`npm run build`。
- 本機使用明確標示的虛構資料，驗證範圍切換、背景篩選、搜尋無結果、個人歷史、空梯次與 390px 手機版。未完成正式帳號端到端驗證。
