# NPTC 量表庫與獨立問卷連結

2026-10-29 已完成量表功能本機驗證、正式資料庫四段升級的唯讀核對，以及 API 簽章與前端公開金鑰同步。本次依使用者授權合併至 `main`，由既有正式網站流程部署。既有功能驗證見 [驗證結果](reviews/2026-10-29-surveys-final-validation.md)，三次示範施測與發布範圍見 [Demo 交付紀錄](reviews/2026-10-29-survey-demo-release.md)。

## 教師操作

1. 執行 `pnpm dev:demo` 後，開啟本機 `/teacher/`，以 `teacher`／`demo1234` 登入。
2. 進入「量表管理庫」，點選「發布管理」後選擇 OSCE 梯次。
3. 在梯次卡片點選「加入量表」，直接由彈出清單選擇，不會切換分頁。量表庫分頁可另行展開完整題目及說明。
4. 從清單選取量表、填寫備註，再選擇立即開放或先保存草稿。
5. 每次加入均建立獨立問卷及短網址；可按「複製短網址」、「分享連結」或「下載 QR code」。QR code 直接下載為 PNG，不展開圖片。再自行貼到課程群組或訊息中，系統不會自動代寄。
6. 教師可修改發布狀態、開放／截止時間及備註。所有時間欄位以臺灣時間輸入，資料庫以 UTC 儲存。
7. 在「問卷完成情形」查看學員是否繳交；如需研究資料，可按問卷或整個梯次匯出 CSV。

備註已依使用者確認設定為「僅老師可見」。備註不包含在學員公告、問卷頁或分享網址中。量表本身的「量表註記」是另一個欄位，會顯示給學員，例如翻譯初稿及版本適用範圍。

同一份量表可加入不同梯次，也可在同一梯次加入多次。每次加入均獨立計算完成狀態。系統不強制分前後測，也不限制哪份須先完成；需要的分類由教師自行備註。

## 量表內容維護（依最新要求暫不開放新增）

量表庫目前有 DTI-SK、使用者提供的 VPIRS-E 繁體中文建議版，以及依使用者 Excel 欄位建立的學習滿意度問卷。兩份新問卷只加入量表庫，不自動發布至任何梯次。

依使用者最新要求，已移除「新增量表至庫」及「建立修訂版」操作，網站先只供查看及選用既有量表。其他量表日後再由使用者安排加入。資料格式保留以下支援：

- 單一敘述＋數字單選。
- 左右兩個敘述＋數字單選。
- 可設定量尺上下限，範圍為 0–10 的整數。
- 量尺兩端文字、反向題及構面名稱。

本次另支援文字意見、文字選項單選及選填題。尚未提供多選、跳題或逐題不同數字量尺。

加入梯次時會保存完整題目快照；日後新增其他版本時，也不會改變已發布問卷或既有作答。可計分量表依問卷快照由伺服器換算，前端不能指定總分；待確認或不計分問卷只保存原答，總分為 null，不當作 0 分。

DTI-SK 使用先前確認的 14 題，保留左右敘述及 1–6 量尺，第 1、5、6、7、10 題使用修訂文字。持續標示「繁體中文翻譯初稿，未經驗證」。其既定反向題及構面分類仍保存於該版本。

## 學員流程

教師分享的新連結格式為 `/q/?s=22碼代碼`，原 `/student/?survey=問卷發布編號` 繼續有效。短代碼保留完整問卷識別，不需要資料庫對照表，也不包含帳密或學員身分。學員未登入時先輸入帳密，登入後接續開啟該份問卷；已登入且符合梯次名冊時直接填答。

本機示範學員：`student-demo@example.test`／`demo1234`。本次將示範登入改為 Email 與密碼，讓試用方式與正式帳密登入相近；正式環境仍沿用既有 StudentLogin 及帳號啟用流程。

單選題不預選答案；文字題依問卷設定顯示必填或選填。繳交後只顯示已完成及收件時間，不回傳學員原答或分數。網路逾時時保留相同提交編號，可重試原作答，避免建立重複紀錄。

「我的 OSCE 成績」頁僅顯示「問卷填寫公告」，列出量表名稱、是否完成、發布與完成時間。題目不直接放在成績頁，未完成且開放中的問卷可由連結前往填寫。公告 API 不含問卷分數、教師備註、題目、反向規則或其他學員資料。原有 OSCE 成績功能不變。

## 本機資料與正式資料分開

`pnpm dev:demo` 使用瀏覽器 localStorage，僅供同一瀏覽器的本機試用。示範連結中的 localhost 網址不能直接讓其他人的裝置連到您的電腦；正式網站與中央資料庫安裝完成後，才可分享正式網址。

本機舊示範資料會保留。原前後測分類移成可編輯的教師備註，不再用來限制填答順序。這是資料格式調整，不代表舊紀錄被刪除或重新計分。

## 正式升級安排與目前狀態

本專案正式資料庫已核對完成四段量表升級，無須為本次前端發布重裝。以下保留給尚未安裝的新環境；GitHub 建置不會自行執行 SQL。

1. 先依主 README 備份資料並完成既有 NPTC 資料庫。
2. 安裝完整 `supabase/upgrade-surveys.sql`。
3. 接著執行完整 `supabase/upgrade-survey-library.sql`。此檔新增量表庫、獨立問卷加入及問卷連結 RPC，移除固定類別限制，保留原始作答與快照。
4. 接著執行 `supabase/upgrade-survey-analysis.sql`，最後執行 `supabase/upgrade-survey-deletion.sql`。
5. 使用 `verify-surveys.sql` 與 `verify-survey-library.sql` 唯讀檢查安裝；完成真實帳號與專用測試梯次驗收後，再部署正式前端。

第二段升級完成後，第一段升級會拒絕單獨重跑，以保護新量表庫流程；之後的重跑使用第二段升級。推送 GitHub 或前端建置不會自動安裝 SQL。示範分數使用下方獨立種子檔，與資料庫安裝分開。

## Demo 示範梯次的三次量表

既有「Demo 示範梯次（20 位學員）」已加入同一版本 DTI-SK 的三次獨立施測，日期為 2026-10-01、10-15、10-29，各有 01–20 號示範學員的 20 份作答，共 60 份。平均總分依序為 48.95、55.95、59.45；每位學員均有三次紀錄，可查看上升、持平或波動的個人走勢。

操作：老師登入 → 學習分析儀表板 → 量表分數與趨勢 → 選擇該 Demo 梯次及 DTI-SK。選擇全部學員查看各次平均，點選示範學員查看個人趨勢，點分數可看逐題作答與反向換算。

三次發布的教師備註均註明模擬資料，狀態為關閉，避免與新的實際填答混合；學員端仍只公告完成情形。這些人工分數僅供操作示範，不能用作學習成效或量表驗證證據，翻譯初稿未經驗證的標註保留。

來源為 `supabase/seed-demo-surveys.sql`，只選取指定梯次、01–20 號名稱及既有已啟用帳號，不建立 Auth 帳號，不改名冊或 OSCE 成績，也不寫入其他梯次。固定發布與提交識別可重跑，既有資料衝突則停止，不覆寫。此檔不納入 `install.sql`，也不會由建置或部署自動執行。本機 `dev:demo` 的瀏覽器資料與此正式資料庫示範梯次分開保存。

資料表仍位於 `nptc_private`，保留 RLS 與無直接資料表權限的設計。老師 API 逐次確認後臺權限；學員 API 確認已啟用帳號及所屬梯次。直接取得其他梯次的問卷編號也不能繳交。

既有封存與永久刪除保護沿用第一段：封存後僅能依角色查看；有作答的學員不能從名冊直接刪除。完整梯次的永久刪除仍需既有管理者重新驗證流程。

## 資料匯出

問卷作答 CSV 包含梯次、學員代碼、獨立問卷編號、量表代碼與版本、教師備註、每題原答及換算、構面及總分。不同問卷題數會補空欄，未填答不會當作零分。姓名、Email、手機與個人背景不包含在研究匯出內；教師仍可和名冊對照，因此不能稱為完全匿名。

不再提供固定前後測配對按鈕；研究者可依問卷編號、備註及學員代碼安排後續分析。

## 量表管理庫與發布管理

後臺選單已改名為「量表管理庫」，內有「量表庫」與「發布管理」兩分頁。發布管理以可點選整列的 OSCE 梯次卡片呈現，名稱與說明靠左、展開控制靠右，問卷內容在卡片下方展開。

每個梯次的「加入量表」會開啟同頁清單，填寫教師備註並確認即可加入，不切換到量表庫。量表庫本身仍可展開題目與指定加入的梯次；新增量表及建立修訂版入口維持移除。

## 老師查看量表分數與趨勢

進入「學習分析儀表板」，選擇「量表分數與趨勢」。可篩選 OSCE 梯次、量表版本、學員姓名及分數項目；分數項目包含總分與該量表定義的構面。

- 選擇全部學員時，圖表呈現各次發布的平均，並列出每個點的有效分數筆數。
- 選擇或點選單一學員時，圖表呈現該學員的歷次分數。
- 橫軸按發布時間排序，標示教師備註；未填備註時顯示發布次序。實際填寫時間列於學員分數明細。
- 不同量表或不同版本分開比較；草稿不列入應填份數，未填答留空，不當作 0 分，也不連接缺漏的資料點。
- 點選分數可查看該次保存的題目、原始答案及換算得分。學員端的 API 及成績頁仍只提供完成狀態。
- 跨梯次以作答帳號串接，保留歷史帳號識別；同名不直接視為同一人。資料範圍沿用後臺角色，系統管理者可包含封存梯次。

## 刪除單次問卷發布

問卷卡片新增「刪除本次發布」。開啟時讀取最新作答筆數及設定版本。

- 尚無作答：確認後刪除該次發布，原填答連結失效。
- 已有作答或分數：明確警示筆數、要求勾選資料永久刪除確認，再輸入目前管理員的 Email 及密碼。帳號必須是目前登入且已啟用的後臺管理員。
- 正式模式使用獨立、不持久保存的 Auth client 重新登入；密碼只送至既有 Auth 服務，不傳入問卷刪除 RPC，也不存入日誌或瀏覽器儲存。
- 後端重新計算筆數並檢查設定版本、管理員權限，以及兩分鐘內的密碼登入與一次性 session。期間有新作答或設定改動會拒絕刪除，須重新讀取警示。
- 刪除僅影響該次發布與它的作答，量表庫原始內容、其他發布及其他梯次保留。刪除事件只留下問卷識別、量表版本、操作者、時間及筆數，不保留被刪除的答案。
- 封存梯次須先依既有管理流程還原，才能刪除問卷。

本機示範刪除驗證使用 `teacher-demo@example.test`／`demo1234`，僅模擬本瀏覽器資料操作，不能當成正式身分驗證結果。

## VPIRS-E 與學習滿意度

VPIRS-E 保留使用者提供的 25 題、五點量尺及四構面（14／4／3／4 題）。第 15 題保留臨床族群調適；第 19–25 題僅註記負向敘述，未設定為反向計分。依使用者決定，正式規則補充前不產生逐題換算、構面分數、總分或趨勢，只提供完成狀態及原始作答。繁中建議版尚未驗證；西班牙文版文獻不代表此中文版已獲驗證。

學習滿意度以使用者提供的 `1109滿意度調查表.xlsx`「表單回應 1」B1:P1 的 15 個欄位為題目，文字逐欄核對一致，保留原課程 I／II 命名與講師文字。未匯入來源的 38 筆回覆。使用者確認：11 題五點滿意度必填、推薦意願「是／否」必填、3 題文字意見選填（每題最多 2000 字）。本問卷保存原始回覆，不建立合成總分。

不計分與待確認問卷在老師分析頁顯示狀態，可點「查看原答」。研究 CSV 的未計分欄位留白，另列計分狀態，文字內容保留試算表公式注入防護。學生端仍只公告完成狀態。

## 短網址與 QR code

短網址使用 22 碼無損編碼，完整保留問卷 UUID；不截斷識別碼、不建立新權限或對照資料表。無效或不完整代碼顯示連結錯誤，不導向任意外站。GitHub Pages 子路徑沿用既有 appUrl 設定。

靜態 `/q/` 頁面在 JavaScript 執行前即提供「問卷填寫｜為國考而訓 NPTC」的 title、description 與 Open Graph 標籤。此版分享卡片使用通用問卷名稱，不將教師備註或學員資訊公開。

下載 PNG 為 1024×1024、四模組留白、M 級容錯，內容與卡片短網址相同。QR 模組僅在點下載時載入，頁面不展開 QR 圖片。來源採 [node-qrcode](https://github.com/soldair/node-qrcode)；已以獨立 jsQR 解碼檢查圖片的實際連結。
